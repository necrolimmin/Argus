# ISUP: камеры Hikvision подключаются к Argus сами

Камера или регистратор Hikvision с включённым **ISUP 5.0** («Доступ к платформе»)
сами звонят на сервер Argus из любой сети. На объекте не нужны белый IP, проброс
портов и VPN: достаточно, чтобы у устройства был интернет.

```
устройство --ISUP 17660 tcp/udp--> isup-bridge <--видео 17661 tcp-- устройство
                                        |  ffmpeg -c copy (без перекодирования)
                                        v
                          go2rtc (тот же поток, что у обычных камер)
```

- В Argus: **Устройства → Добавить → Камера подключится сама**. Argus выдаёт каждому
  устройству **Device ID** и **ключ шифрования**, их вписывают в устройство.
- Как только устройство подключилось, его камеры появляются сами (у регистратора по
  одной на канал), статус «В сети».
- Дополнительный поток каждой камеры открыт постоянно (дёшево: стена, распознавание).
  Основной открывается, когда его кто-то смотрит, и закрывается через минуту после.
- Чужое устройство без нашего ключа не подключится. Попытки с неизвестным Device ID
  видны на странице «Устройства», такое устройство можно добавить одной кнопкой.

Сервис `isup-bridge` написан для Argus по схеме пилотного моста проекта Vizora;
последовательность вызовов Hikvision SDK взята оттуда, она проверена на реальных
устройствах.

## 1. Hikvision ISUP SDK

SDK закрытый и в репозиторий не кладётся (`isup/sdk/` и `isup/inc/` в `.gitignore`).
Выбран вариант с неофициальной сборкой: github.com/135356/hikvision_isup, релиз 0.2.0,
файл `hikvision_isup_0.2.0_Linux_x86_64.tar.gz` (внутри ещё один gzip).
Официально SDK выдаёт Hikvision через TPP по запросу; если он придёт, кладётся так же.

На сервере, в папке проекта:

```bash
cd /tmp && mkdir isup-sdk && cd isup-sdk
# скачайте архив релиза сюда, затем:
tar xzf hikvision_isup_0.2.0_Linux_x86_64.tar.gz
# если внутри снова .gz/.tar.gz — распакуйте и его
cp -r <распакованное>/build/*.so* <распакованное>/build/HCAapSDKCom /home/Argus/isup/sdk/
# заголовки в кодировке GBK: компилятору нужны в UTF-8
cd <распакованное>/include/hikvision
for f in *.h; do iconv -f GBK -t UTF-8 -c "$f" > /home/Argus/isup/inc/"$f"; done
```

В `isup/sdk/` должны оказаться: `libHCISUPCMS.so libHCISUPStream.so libhpr.so
libHCNetUtils.so libcrypto.so* libssl.so* libz.so libsqlite3.so libNPQos.so
libHCISUPAlarm.so libHCISUPSS.so` и папка `HCAapSDKCom/`.

## 2. Настройка сервера

В `.env` (рядом с `docker-compose.yml`):

```
COMPOSE_PROFILES=isup
ARGUS_ISUP_PUBLIC_IP=<внешний IP офиса, на который будут звонить устройства>
```

На роутере пробросьте на сервер (192.168.5.103):

| Порт | Протокол | Зачем |
|---|---|---|
| 17660 | TCP и UDP | регистрация устройств |
| 17661 | TCP | видео |

Затем:

```bash
cd /home/Argus && git pull
docker compose up -d --build
docker compose logs -f isup-bridge
```

В логе должно быть: `ISUP bridge ready: registration 17660 tcp/udp, video 17661 tcp ...`.
Если сборка пишет `isup/sdk/ is empty`, SDK не на месте (шаг 1).

Устройства внутри офиса лучше добавлять обычным способом, по IP: ISUP нужен для
объектов в других сетях. Если устройство из офисной сети всё же настроить на внешний
IP, оно упрётся в ту же проблему роутера, что и сайт (hairpin NAT).

## 3. Настройка устройства (один раз)

Веб-интерфейс камеры или регистратора → **Конфигурация → Сеть → Расширенные
настройки → Доступ к платформе (Platform Access)**:

| Поле | Значение |
|---|---|
| Тип доступа | ISUP |
| Включить | да |
| Версия протокола | 5.0 |
| Адрес сервера | `ARGUS_ISUP_PUBLIC_IP` |
| Порт | 17660 |
| Device ID | из Argus |
| Ключ шифрования (Encryption Key) | из Argus |

Сохранить. Через 10–20 секунд «Состояние регистрации: Онлайн». Если устройство долго
не подключается после неудачных попыток, выключите ISUP, сохраните и включите снова.

Кодек: если на камере H.264, нагрузки на сервер почти нет. H.265 тоже показывается
(браузер играет его через MSE), но не во всех браузерах.

## 4. Если не работает

```bash
ss -lntup | grep -E ":1766[01]\b"                 # порты слушаются
sudo tcpdump -ni any "port 17660 or port 17661"  # пакеты от устройства доходят
docker compose logs --tail 100 isup-bridge
```

| В логе | Что значит |
|---|---|
| `connected <ID> ...` | устройство подключилось |
| `rejected <ID>: no such device ID in Argus` | этого Device ID нет в Argus: добавьте (на странице «Устройства» есть кнопка) |
| `<ID>: the encryption key on the device does not match` | ключ в устройстве не тот, что в Argus |
| `rejected <ID>: registered without the ISUP 5.0 key check` | на устройстве выбрана не версия 5.0 |
| `first video after 0.3s` | видео пошло |
| `no video, will retry` | канал не отдаёт видео (нет такого канала или потока), повтор через 3–60 с |
