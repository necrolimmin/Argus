# Argus

Единая система видеонаблюдения для камер Hikvision, Dahua и любых RTSP-камер,
с распознаванием лиц и учётом входа и выхода сотрудников.

## Состав

| Сервис       | Что делает                                                                 |
|--------------|-----------------------------------------------------------------------------|
| `frontend`   | React + TypeScript (Vite), раздаётся через nginx, проксирует `/api` на бэкенд |
| `backend`    | FastAPI + PostgreSQL: структура, камеры, сотрудники, события, WebSocket       |
| `go2rtc`     | Отдаёт видео в браузер по WebRTC; держит одно подключение к каждой камере     |
| `recognizer` | InsightFace на GPU: анализирует камеры с распознаванием и шлёт события        |
| `db`         | PostgreSQL 16                                                               |

Видео не проходит через бэкенд: браузер получает его напрямую от go2rtc.
Бэкенд только проверяет права и передаёт SDP-рукопожатие.

## Запуск на сервере (Ubuntu + NVIDIA)

1. Установите Docker и [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).
2. `cp .env.example .env` и заполните. Обязательно задайте:
   - `ARGUS_PUBLIC_HOST`: IP сервера, по которому к нему обращаются компьютеры операторов;
   - секреты и пароль первого администратора;
   - `ARGUS_ENCRYPTION_KEY`: им шифруются пароли камер, после запуска не меняйте.
3. `docker compose up -d --build`
4. Откройте `http://<сервер>/` и войдите под администратором из `.env`.

Порты: `80` (интерфейс), `8555/tcp` и `8555/udp` (видео WebRTC). Остальные
порты наружу не публикуются.

При первом старте `recognizer` скачивает модели лиц (около 300 МБ) в volume `models`.

## Настройка камер

- В сетке показывается **дополнительный поток**, на весь экран — **основной**.
- Камеры можно оставить на **H.264 или H.265**, менять настройки камеры не нужно.
  Плитка сначала пробует WebRTC (минимальная задержка). Если браузер не смог
  так показать видео, она сама переключается на MSE. Chrome и Edge на Windows
  показывают H.265 через видеокарту компьютера оператора, сервер видео не
  перекодирует.
- Для камер с распознаванием дополнительный поток лучше поднять до 1280×720.
  Иначе лица у входа получаются мелкими. Можно также переключить поток
  распознавания на основной в карточке камеры, но это нагружает процессор.

## Распознавание

- Работает в фоне по расписанию каждой камеры. Где расписание не задано —
  круглосуточно.
- Экономный режим: 1 кадр/с, пока в кадре никого нет, 5 кадров/с, пока есть лица
  (`ARGUS_IDLE_FPS`, `ARGUS_ACTIVE_FPS`).
- Один и тот же сотрудник на одной камере записывается не чаще раза в
  `ARGUS_DEDUP_SECONDS` (60 с). Неопознанный человек даёт одно событие
  с лучшим кадром.
- Порог совпадения: `ARGUS_MATCH_THRESHOLD` (0.45). Если система путает людей,
  повышайте; если не узнаёт своих, понижайте.
- События и снимки хранятся `ARGUS_RETENTION_DAYS` дней (60).

## Разработка

```bash
# backend
cd backend
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest
ARGUS_DATABASE_URL=sqlite+aiosqlite:///dev.db .venv/bin/alembic upgrade head
ARGUS_DATABASE_URL=sqlite+aiosqlite:///dev.db ARGUS_MEDIA_DIR=./media .venv/bin/uvicorn app.main:app --reload

# frontend (проксирует /api на localhost:8000)
cd frontend && npm install && npm run dev

# логика распознавателя (без GPU)
cd recognizer && PYTHONPATH=. pytest tests
```

### Локально на Windows

Четыре терминала. Настройки бэкенда уже лежат в `backend\.env`.

| Что          | Команда                                                                 |
|--------------|--------------------------------------------------------------------------|
| Бэкенд       | `cd backend` → `.venv\Scripts\uvicorn app.main:app --reload --port 8000` |
| Фронтенд     | `cd frontend` → `npm run dev`, затем http://localhost:5173              |
| Видео        | `cd D:\Tools\go2rtc` → `.\go2rtc.exe -c go2rtc.yaml`                     |
| Распознавание| `recognizer\run-local.cmd` (зависимости: `pip install -r requirements-windows.txt`) |

Распознавание на Windows работает на видеокарте через DirectML.
Нейросети (около 280 МБ) скачиваются при первом запуске в `%USERPROFILE%\.insightface`.

Документация API: `http://<сервер>/api/docs`.

## Устройства

- **Устройство** — камера или регистратор (IP, порты, логин и пароль). **Камера** — канал устройства, у каждой своё подразделение и настройки распознавания.
- Способы добавления: вручную по шаблону производителя, «Любая ONVIF», RTSP/HTTP-ссылка, сканирование сети, импорт из Excel/CSV.
- Hikvision и Dahua читаются через свой веб-интерфейс (ISAPI/CGI): модель, серийный номер, каналы регистратора, снимок. У Hikvision ONVIF по умолчанию выключен, поэтому для них используйте шаблон Hikvision.
- **Сканер сети** в Docker — отдельный сервис `scanner` с `network_mode: host`. Автопоиск (ONVIF, SADP, Dahua) видит только свой сегмент сети. Камеры в других подсетях ищутся по диапазону адресов.
- Статус «в сети» проверяется раз в минуту.
- После обновления до этапа 2 нужна миграция базы: в Docker она выполняется сама при старте бэкенда. Локально выполните `.venv\Scripts\alembic upgrade head` в папке `backend`.

## Этапы

1. **Камеры** и **Сотрудники и учреждения** (готово).
2. **Устройства** (готово): устройства и каналы, ONVIF, импорт с регистраторов, сканирование сети, Excel.
3. **Интеграция API**: внешние системы, табель, отчёты, выгрузка в Excel.
