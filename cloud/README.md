# Камеры из аккаунтов Hik-Connect и EZVIZ

Argus входит в аккаунт Hik-Connect или EZVIZ так же, как приложение на телефоне,
видит камеры и регистраторы аккаунта и показывает выбранные. Видео идёт через облако
производителя: на объекте не нужны белый IP, проброс портов и какие-либо настройки
камеры.

```
облако Hik/EZVIZ (ретранслятор) --> cloud-bridge --> ffmpeg -c copy --> go2rtc
```

- В Argus: **Устройства → Добавить → Из аккаунта Hik-Connect / EZVIZ**. Логин и пароль
  те же, что в приложении. Если в аккаунте включён вход с подтверждением, облако
  пришлёт владельцу код, Argus его спросит.
- После входа отмечаются камеры (у регистратора по каналам), и они появляются в
  Argus как обычные.
- Поток открывается, только пока его кто-то смотрит (и минуту после), или если по нему
  работает распознавание лиц. Так не тратится канал владельца и терпение облака.
- Перекодирования нет: ffmpeg только копирует поток, нагрузка на CPU минимальная.

## Что включить на сервере

Ничего: служба `cloud-bridge` запускается вместе с остальными
(`docker compose up -d --build`). Серверу нужен выход в интернет к облаку
(`*.hik-connect.com`, `*.ezvizlife.com`, для СНГ `*.hik-connectru.com`, `*.ezvizru.com`)
по HTTPS и к ретрансляторам облака по TCP.

```bash
docker compose logs -f cloud-bridge
```

| В логе | Что значит |
|---|---|
| `cam_…: video h264, publishing` / `playing` | видео пошло |
| `encrypted` | у устройства включено **«Шифрование видео»**: выключите его в приложении (настройки устройства). Расшифровку Argus пока не делает |
| `offline` | устройство не в сети или его нет в аккаунте |
| `failed … no video from the device` | облако приняло запрос, но устройство не прислало видео; повтор через 3–60 с |
| `cloud session ended, renewing` | облако завершило сеанс; Argus сам войдёт заново |
| `no sub stream, using the main one` | у камеры нет дополнительного потока в облаке, используется основной |

## Запуск без Docker (на компьютере разработчика)

Нужны Python 3.12 и `ffmpeg` в `PATH`. Сначала должны работать go2rtc и бэкенд.

Один раз:

```powershell
cd D:\Project\Argus\cloud
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
```

В `backend\.env` должна быть строка, чтобы бэкенд искал мост на этом же компьютере:

```
ARGUS_CLOUD_BRIDGE_URL=http://127.0.0.1:8092
```

Каждый запуск (PowerShell):

```powershell
cd D:\Project\Argus\cloud
$env:API_TOKEN = (Select-String -Path ..\backend\.env -Pattern '^ARGUS_SERVICE_TOKEN=(.*)$').Matches[0].Groups[1].Value
$env:RTSP_BASE = "rtsp://127.0.0.1:8554"
.\.venv\Scripts\python.exe bridge.py
```

Вторая строка читает токен из `backend\.env` сразу в переменную, на экран он не выводится.
Токен должен совпадать с `ARGUS_SERVICE_TOKEN` бэкенда, иначе бэкенд не сможет говорить с мостом.
При успешном старте в логе будет
`cloud bridge ready: API 8092, publishing to rtsp://127.0.0.1:8554`.

## Безопасность

- Пароль аккаунта хранится зашифрованным (тем же ключом, что и пароли камер) и
  отправляется (как MD5, так требует облако) только на домены Hikvision/EZVIZ:
  любой другой адрес, в том числе из ответа облака, отклоняется.
- При неверном пароле Argus не повторяет вход чаще раза в 15 минут, чтобы облако не
  заблокировало аккаунт.
- Для облака Argus выглядит как ещё один телефон владельца.

## Ограничения

- Камеры с включённым «Шифрованием видео» не показываются (будет сообщение).
- Аккаунты Hik-Connect for Teams (бизнес-версия) не поддерживаются.
- Протокол облачного ретранслятора взят из библиотеки pyEzvizApi (Apache-2.0); облако
  может его поменять, тогда понадобится обновить библиотеку.

Тесты моста (без сети): `cd cloud && python -m pytest -q` (нужны `pip install -r
requirements.txt pytest` и ffmpeg).
